Authentication

Use a simple JWT auth system.

Implement:

POST /auth/register

POST /auth/login

Optional /auth/me to fetch current user

Password hashing with bcrypt

JWT signing and verification

Middleware: requireAuth, requireAdmin

User roles:

admin

investor

Store users in Replit Database under keys like:

users:<id> = {
  "id": "string",
  "name": "string",
  "email": "string",
  "passwordHash": "string",
  "role": "admin" | "investor",
  "created_at": "ISO string"
}

Backend API Routes (Express)
Properties

GET /api/properties – list properties with filters

GET /api/properties/:id – single property

POST /api/properties – admin create

PUT /api/properties/:id – admin update

DELETE /api/properties/:id – admin delete

Commitments

POST /api/commitments – create commitment

GET /api/commitments/property/:propertyId – admin view commitments for a property

PUT /api/commitments/:id/approve – admin approve

PUT /api/commitments/:id/reject – admin reject

Documents

POST /api/documents/upload – admin upload, save file in /uploads and record in DB

GET /api/documents/:propertyId – list property documents

Comps

POST /api/comps – admin create or bulk create

GET /api/comps/:propertyId – list comps for property

AI BPO Extraction

POST /api/ai/extract-bpo

Input: base64 PDF or JPEG

Use Gemini to extract purchase price, ARV, rehab estimate, list of comparable sales

Update property and comps accordingly

Auth

POST /api/auth/register

POST /api/auth/login

GET /api/auth/me

Use JWT cookies or bearer tokens for the frontend.
